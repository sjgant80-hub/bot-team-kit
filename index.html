bot-team-kit

A company run by bots, overseen by a human. This is its nervous system: one shared feed every bot reads and writes, a writer that redacts secrets and flags unproven claims, a deterministic daily rollup with NEEDS SIMON at the top, and a mutation gate that proves the tests actually catch breakage.

1 · What it is, in plain words

A small team of AI bots can only be trusted if their work is checked, not just produced. This kit gives the team the one thing that makes checking possible: a single shared log of every action, written in a way that can't leak a secret and can't quietly claim "done" without a proof. A separate auditor bot and a human (Simon) read that log; anything public, paid, or risky stops and waits for the human's signature.

2 · Start here — use it in 30 seconds

git clone https://github.com/sjgant80-hub/bot-team-kit
cd bot-team-kit

# a bot records an action (secrets are stripped, unproven "done" is flagged)
node src/feed.mjs --agent BUILDER --kind build \
  --what "feed writer gated, 9/9 mutants killed" \
  --receipt 9b15d4ff54fb189cf942fae1528037d3bcb496d5ca84c1bbe6af840e98dd57c5

# build the morning brief Simon reads
node src/rollup.mjs --out AGENT_FEED.md

# prove it yourself
node --test test/test.mjs   &&  node gate.mjs

4 · The blueprint — organ by organ

organjob
src/kernel.mjspure, total functions — redact, flagsFor, validateLine, rollup. Never throws on garbage. This is the gated surface.
src/feed.mjsappend one redacted + flagged + valid JSON line to the feed (CLI + library).
src/rollup.mjsread the feed → write the morning rollup, NEEDS SIMON first.
schema.jsonthe contract for a feed line.
gate.mjsbreaks the kernel 9 ways and proves every break is caught. A survivor turns the gate red.
test/1000-line redaction fuzz (0 leaks), both flag branches, golden rollup determinism.
skills/feed-write/the first reusable team skill, multi-runtime frontmatter.

5 · The roster & the rules

KAR — conductor. Reads the feed, assigns, writes the rollup. Never ships or spends.
BUILDER — builds against the gate, seals claims. Never merges or releases without the auditor + Simon.
AUDITOR — separate judge. Claims vs receipts, re-runs tests. Never builds.
MONEY TIME · REACH · SCOUT · CLIENT LEAD · CARD KEEPER — sell, post, watch, intake, sign. Each stays in its lane.

Ten rules govern the team (one role per bot · seal "done" first · every claim links a re-runnable receipt · allowed tools only · the auditor checks everything before it moves · NEEDS SIMON for anything public/paid/risky · plain language · no earnings or crypto claims · follow platform rules · failures stay on record).

6 · For your team

If you run more than one AI agent, you already have the problem this solves: who did what, was it true, and did anything leak. Point every agent at one feed.mjs, read the rollup each morning, and let a separate auditor re-run the receipts. It's one file to adopt, MIT, zero dependencies, and every claim it makes about itself is one command away from proof.
