bot-team-kit

One shared feed for a team of AI bots that a person oversees. Every bot writes what it did to the same file; keys, tokens, passwords, emails and card numbers are stripped out and unproven "done" claims are flagged before anything is saved; and each morning one page — with NEEDS SIMON at the top — says what the bots did and what is waiting for a person.

What it is, in plain words

A small team of AI bots can only be trusted if its work is checked, not just produced. This kit is the one piece that makes checking possible: a single shared log of every action, written so that no secret of a shape the kit has a rule for ever reaches it, and no "done" without proof passes quietly.

A separate auditor bot and a person read that log. Anything public, paid or risky stops and waits for the person. The kit is a small kernel with a writer and a rollup around it, a schema, and a ready-made skill for the bots — it runs on the machine the bots already run on and talks to nothing else.

The blueprint — organ by organ

  
Each organ, what it does, the tests that hold it, and what witness  found when it broke the organ on purpose — every comparison and logic operator flipped, one at a time, with the tests run against each broken copy. A broken copy the tests still pass is a hole. The one exception is a copy that behaves exactly like the original, which no test can tell apart: witness lets such a survivor be exempted only with a written reason, and it is shown in its row with that reason — here the one exemption is backed by test/equivalence-1c.mjs, which builds that exact broken copy and compares it with the real code on every short input, on GitHub's runner on every change. Each file's SHA-256 prefix is the version witness measured. White paper — why one feed

  

    
The problem

    
When several AI agents share work, things go wrong quietly. Work is claimed and not done — "shipped", "tests passed" — and nobody checks. Secrets travel: an agent pastes a key into a status message and it sits in a log for good. And the person in charge has no single place to see what happened, so oversight becomes asking each agent in turn, and believing it.

    
The design

    
One feed. Every action is one JSON line in one file that the kit only ever appends to, so there is one place to look and hand-offs happen in the open. Clean at the door. The writer strips every secret shape it has a rule for from every string in the line, at any depth, before anything touches disk — a refused line comes back redacted too. Claims carry proof. A line that says work is finished — a finishing word that is not negated, or a build or receipt line — must carry a receipt hash or a proof link, or it is flagged. A page a person can trust. The rollup prints each field on one physical line and redacts it again, so neither formatting nor a line written by another tool can forge or leak into it, and lines it cannot read are reported, not dropped. A separate judge. The kit checks the shape of proof; the auditor re-runs it, and anything public, paid or risky waits for the person.

    
The evidence

    
Reading the first build's code found it redacted only top-level text, missed common key shapes, read a card followed by its security code as one wrong number, accepted "see above" as proof, and let a line break forge a heading. The fix was sealed before it was written. Measured once against the sealed batteries: the first build leaked  of  secret shapes and the fixed code leaks ; it flagged  of  unproven claims and now flags , while flagging  of  lines that claim nothing;  of  lines holding no secret pass through untouched; the forged rollup fails  of  structure checks on the first build and none now. The first build's own fuzz of  generated secrets still leaks none. And the page that reports all this is held to the same bar: the code that fills in its numbers, gives each claim its verdict and checks the page itself is mutation-gated on GitHub's runner too.

    
What it does not claim

    
The batteries were written by the same hand that fixed the code, after reading it: they show which shapes are covered, not how a stranger's wording would fare. Lines are not signed here — anything that can write the file can write a line under any name; the signed team feed, which binds each line to its bot's key, is in ai-first-company. And the kit checks that a proof looks like a proof; whether it is true is the auditor's job.

    
Where it fits

    
This is the nervous system of a company run by bots and overseen by a person: the shared feed, the rules a file can enforce, and the morning page. The team, its fences, its signed feed and its separate auditor are built in ai-first-company; the mutation gate is witness.

    Risks, answered straight
    
    
      
    What if a secret has a shape the kit does not know?
    It is stored as written. The kit removes the shapes its rules cover — the sealed battery lists them, and the fixed code leaks none of them. Adding a shape is one line and a test, and the morning page applies it to old lines too. The first defence is still to keep secrets out of what bots write.
    
      
    Can a bot fake "done"?
    It can write the words, and the flag still comes: a claim without a receipt hash or a proof link is flagged and goes to the top of the page. A bot escapes the flag only by attaching something shaped like proof — and the kit checks the shape, not the truth, so that proof is exactly what the separate auditor re-runs.
    
      
    What if a bot stops writing to the feed?
    The kit sees only what is written. Each bot that wrote has its own section on the morning page, so a bot that goes quiet shows as a missing section — and work with no line in the feed is what the auditor looks for when it compares the feed with the work itself.
    
      
    Can a bot pretend to be another bot?
    In this kit, yes: lines are not signed, so anything that can write the file can write any name. Formatting cannot forge the page, which is measured. For lines bound to each bot's own key, use the signed feed in ai-first-company.
    
      
    What if the feed file is damaged?
    Lines that cannot be read are counted and reported as a blocker at the top of the page, never dropped in silence — measured on a damaged feed.
    
      
    What about personal data such as names?
    Emails and card numbers are removed; names and free text are not. Bots should record actions, not customer records — and a rule can be added for any identifier you handle.
    
      
    Is it tied to one AI vendor?
    No. Any agent that can run Node.js — or append one JSON line — can use it, and the page reads the same whichever model wrote the lines.
    
      
    Who checked the checks?
    The mutation gate: witness broke every organ, and this page's own modules, one operator at a time, on GitHub's runner. The tests caught every broken copy of the organs; of the page's modules, the one copy they cannot catch behaves exactly like the original, and that is shown with its reason and checked on every change, not argued. The test batteries were written after reading the code and say so; the gate is the independent check that the tests bite.
    
      
    Could someone edit or reorder the feed file itself?
    The kit only appends; it does not lock or sign the file, so protect it as you would any log — with the machine's file permissions. Where you need tamper evidence, the signed team feed in ai-first-company chains and signs every line.
    
      
    What if two bots write at the same moment?
    Each line goes to disk in one append call, and any line that ever comes back unreadable is counted and reported at the top of the page — never dropped in silence.
    
      
    Does the feed file grow forever?
    It grows by one line per action, and the morning page reads all of it. Rotate it as you would any log: move the old file aside — keep it, it is your record — and the writer starts a new file at the same path on the next line; the morning page then covers the new file.
    
      
    Our bots run on several machines.
    The kit keeps one feed per machine, each with its own morning page. Merging signed feeds from several machines into one is what the team feed in ai-first-company does.
    
      
    Is it certified?
    There is nothing of ours to certify: the kit runs on your machines, under your controls, and calls no service of ours or anyone else's. What you can check is the code itself, and the receipts that prove what it does.
    
      
    Is anyone using it? Can we talk to a reference customer?
    No reference customer is named on this page, and none is claimed. The evidence here does not rest on anyone's word: every number is a receipt you can re-run, and the quickest proof for your business is a fortnight on one of your own teams, comparing the hours.
    
      
    Which version would we be running, and is it the one these receipts measured?
    Adopt a fixed commit of the repository, not a moving branch. receipts/witness.json names the SHA-256 of every file it gated — the prefixes are in the blueprint — and the sealed claims name the files they measure, so your team can hash its copy and see that it is the code these receipts were measured on.
    
      
    What does it need to run?
    Node.js on the machine the agents already use. The work per line takes a moment of processor time.
